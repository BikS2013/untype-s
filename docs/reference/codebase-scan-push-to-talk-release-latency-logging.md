# Codebase Scan — untype-s

## 1. Project Overview
`untype-s` is a SwiftPM macOS package with one shared runtime library target, `UntypeCore`, and two executable targets: the main `untype` command and the `untype-input-helper` focused-input helper. The project already has a native UI launcher, a shared transcription/runtime pipeline, and structured protocol/settings file persistence, so this request extends an existing push-to-talk release path rather than introducing a new subsystem. The new work is likely to land in the UI/runtime/config/logging seam and in the project docs that already describe Quick Close, release diagnostics, and manual smoke tests.

## 3. Conventions
- The executable targets are intentionally thin and defer almost everything to `UntypeCore`; `Sources/untype/main.swift:4-27` uses `@main` plus `UntypeCommand`, while `Sources/untype-input-helper/main.swift:5-11` is a minimal stdin/stdout wrapper.
- Configuration is strict and layered. `EnvChain` reads `<cwd>/.env`, `~/.tool-agents/untype/.env`, then shell env; `ConfigResolver.resolve(argv:)` parses CLI flags first and raises typed `UntypeError.invalidConfiguration` / `UntypeError.missingConfiguration` errors instead of inventing fallback values. See [`EnvChain.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/EnvChain.swift#L15-L49), [`ConfigResolver.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/ConfigResolver.swift#L45-L178), and [`UntypeError.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeError.swift#L1-L21).
- File-backed state uses dedicated writers with explicit permissions, but the current helper is not append-oriented. `ProtocolSettingsStore` writes pretty-printed JSON to `~/.tool-agents/untype/state.json` with `0700`/`0600` permissions, while `FileTextOutput` truncates the file on open and then writes in place. See [`ProtocolSettingsStore.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/ProtocolSettingsStore.swift#L13-L68) and [`StreamWriter.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/StreamWriter.swift#L20-L47).
- The runtime already uses privacy-safe diagnostics instead of a logging framework. `TranscriptionSessionRuntime` emits release/finalization/submission messages through `ProtocolControllerDiagnostics`, and the native UI keeps a bounded, deduplicated event log via `appendEvent` rather than unbounded file logging. See [`TranscriptionSessionRuntime.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/TranscriptionSessionRuntime.swift#L342-L520) and [`NativeUntypeUILauncher.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/NativeUntypeUILauncher.swift#L790-L802).
- Focused-input delivery and clipboard writing already preserve privacy boundaries. `FocusedInputDelivery` sends processed text through helper stdin, parses a single-line JSON result, and surfaces accessibility/target metadata only through typed result fields; `MacOSClipboardWriter` writes directly to the pasteboard and throws privacy-safe errors. See [`FocusedInputDelivery.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/FocusedInputDelivery.swift#L137-L218) and [`MacOSClipboardWriter.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/MacOSClipboardWriter.swift#L4-L24).
- The native UI owns the push-to-talk release entry point and the runtime assembly boundary. `startHotkeySession`/`stopHotkeySession` fire the release lifecycle, `ConfigResolver(requireProtocolOutputForHybrid: false)` and `UntypeRuntimeFactory.makeForUI` build the runtime, and `UntypeUISettings` / `UntypeUISettingsPatch` already carry non-secret toggle plumbing such as `quickClose` and `focusedInput`. See [`NativeUntypeUILauncher.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/NativeUntypeUILauncher.swift#L340-L375) and [`UntypeRuntimeFactory.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeRuntimeFactory.swift#L93-L190), plus [`UntypeUISettings.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeUISettings.swift#L3-L250).

### New Integration Points
- There is no existing append-only latency logger in the tree. The clean landing site is a new `ReleaseLatencyLogger`/`LatencyLogWriter`-style type under `Sources/UntypeCore`, adjacent to [`ProtocolJsonlWriter.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/ProtocolJsonlWriter.swift) and [`StreamWriter.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/StreamWriter.swift), but backed by an append-capable file handle rather than the current truncating `FileTextOutput`.
- The new opt-in toggle should likely start life as a non-secret configuration field in [`UntypeUISettings.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeUISettings.swift) and [`ConfigResolver.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/ConfigResolver.swift), then be threaded through [`UntypeRuntimeFactory.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeRuntimeFactory.swift) into the session/runtime options and surfaced in [`UntypeCommand.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Sources/UntypeCore/UntypeCommand.swift) help text and the native UI inspector.

## 5. Notes
- The request is a partial extension, not a duplicate feature. Release-to-input timing already has stage diagnostics in `TranscriptionSessionRuntime` and UI event surfacing in `NativeUntypeUILauncher`; what is missing is a durable, append-only file log and the config/documentation plumbing for it.
- Current `appendEvent` storage is bounded and deduplicated, so it is useful for live UI feedback but not sufficient as the only analysis artifact for latency work.
- Existing tests already cover release finalization, Quick Close, timeout fallback, focused-input privacy, config/session-argument redaction, and protocol JSONL sequencing, but there is no dedicated latency-log test coverage yet. See [`TranscriptionSessionRuntimeTests.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Tests/UntypeCoreTests/TranscriptionSessionRuntimeTests.swift#L148-L220), [`UntypeUISettingsTests.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Tests/UntypeCoreTests/UntypeUISettingsTests.swift#L5-L76), [`ProtocolCoreTests.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Tests/UntypeCoreTests/ProtocolCoreTests.swift#L125-L187), and [`FocusedInputDeliveryTests.swift`](/Users/giorgosmarinos/aiwork/coding-platform/untype-s/Tests/UntypeCoreTests/FocusedInputDeliveryTests.swift#L30-L87).

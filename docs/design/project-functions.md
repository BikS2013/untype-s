# untype-s Functional Requirements

## Functional Requirements
- FR-1: The project MUST build a Swift executable product named `untype`.
- FR-2: `untype --help` MUST exit `0` and document commands, flags, env aliases, and usage examples equivalent to the source project.
- FR-3: `untype --version` MUST exit `0` and print the replacement project's semantic version.
- FR-4: The configuration resolver MUST preserve the source precedence order: CLI flag, current working directory `.env`, `~/.tool-agents/untype/.env`, then shell environment.
- FR-5: Missing required configuration MUST raise typed errors and MUST NOT be replaced by fallback values.
- FR-6: Human transcript output MUST remain separate from diagnostics: transcript/protocol output on stdout, diagnostics/warnings/errors on stderr unless UI mode owns rendering.
- FR-7: The macOS microphone path MUST use native Swift audio capture and emit provider-ready mono PCM at the configured sample rate.
- FR-8: The Soniox provider MUST preserve realtime transcription, partial/final handling, marker filtering, commit/finalization, and typed error mapping.
- FR-9: The ElevenLabs provider MUST preserve realtime transcription, base64 audio chunking, manual/VAD commit, partial/final handling, and typed error mapping.
- FR-10: Rendering MUST support `overwrite`, `append`, and `final-only`, including non-TTY overwrite downgrade and duplicate partial suppression.
- FR-11: The voice-agent protocol MUST preserve marker matching, operator state, section lifecycle, JSONL event schema, and non-secret persisted settings.
- FR-12: LLM refinement MUST preserve Azure OpenAI and Google behavior, fail-open runtime semantics, and accepted stubs for non-implemented providers.
- FR-13: Focused-input delivery MUST not pass processed text through process arguments, persisted settings, or diagnostic logs.
- FR-14: `untype ui` MUST reach native UI parity before the project is declared a final drop-in replacement.
- FR-15: Automated tests MUST cover config, parsers, renderer, protocol, persistence, provider adapter mapping, LLM behavior, and CLI contract behavior.
- FR-16: Manual smoke tests MUST document real microphone, live provider, Accessibility/Input Monitoring, focused input, push-to-talk, overlay, and UI checks.
- FR-17: The native UI MUST let users explicitly copy or save the currently retained transcript timeline and event log without automatic background persistence.
- FR-18: The native UI MUST expose a current-session conversation history view that shows retained raw dictated user text and recorded refine/translate processed output without persisting the history content across app launches.

## Non-Functional Requirements
- NFR-1: Swift Package Manager is the authoritative build and test entry point.
- NFR-2: Runtime dependencies must be minimized and vetted before adoption.
- NFR-3: Secrets, transcripts, processed sections, provider endpoints, and protocol payloads must not be persisted where the source project forbids them.
- NFR-4: Work must be decomposed into autonomous phases with durable handoff artifacts.
- NFR-5: No version-control operation may be performed unless explicitly requested.

The native UI now exposes a Push to Talk press/release fallback button that exercises the same overlay/audio-gate path as the keyboard hotkey, records privacy-safe hotkey event-source diagnostics in the UI event log, removes invalid tap-disabled event bits from the Quartz event-tap mask, and raises the overlay to status-bar level on the screen containing the pointer so it is less likely to be hidden behind other windows.

The primary session button now routes hotkey-owned warm sessions through the warm-session stop path, cancels startup tasks when a runtime is not assigned yet, resets UI state to idle on startup cancellation, and the runtime/provider stop paths now honor stops issued during provider startup so startup cannot continue into `listening` after the user clicks `Stop Warm Session`.
- 2026-05-24: FR-14 microphone activity visibility was added after manual listening gave no visible evidence that audio was being captured before STT text arrived. The runtime now emits privacy-safe audio activity snapshots from raw PCM chunks, and the native UI shows an `Audio` status in the header and System panel with `waiting`, `silent`, `active`, or `muted` plus a peak percentage. Closed push-to-talk gates report `muted` while still proving the microphone path is receiving PCM.
- 2026-05-24: FR-7/FR-14 startup ordering was adjusted so microphone capture starts before the realtime STT WebSocket connection completes. This gives immediate UI evidence of capture and separates microphone problems from provider connection problems. Startup diagnostics now report `starting microphone capture`, `microphone capture started`, `connecting <provider> realtime stream`, and `<provider> realtime stream connected`.
- 2026-05-24: FR-14 push-to-talk audio status wording was clarified after the UI could appear not to hear speech while a warm push-to-talk session was intentionally gating audio. Closed push-to-talk gates now report `muted by push-to-talk <n>%`, distinguishing intentional gate muting from silent microphone input or a waiting capture path.
- 2026-05-24: FR-14 UI launch scheduling was fixed after `Session: listening` never appeared in the native UI. The executable now launches `untype ui` directly on the initial main thread before entering the async command path, and UI runtime tasks/callbacks no longer depend on Swift main-actor jobs that are starved by the blocking AppKit run loop. Live UI automation verified startup reaches `Session: listening`, microphone/provider diagnostics appear, push-to-talk recording opens the gate, transcript text appears, and release returns to warm mode.
- 2026-05-24: FR-14 settings-pane visual polish was added. The native UI settings form now uses material-backed glass sections and fixed-width label/control rows so credential/system status, provider controls, protocol operators, LLM settings, and push-to-talk actions align consistently while preserving existing bindings and active-session disabled states.
- 2026-05-24: FR-11/FR-14 push-to-talk release finalization was fixed. Runtime submission now waits briefly for provider final text when no final buffer is available yet, then submits the pending section before shutdown ends the protocol session. The UI now treats each push-to-talk release as the end of that provider-backed content collection turn, stops the provider session, restarts a fresh warm session for the next press, and clears stale live partial text on the next press. This allows processed/refined/translated monitor output plus clipboard and focused-input delivery to run from finalized text instead of leaving only partial transcript lines.
- 2026-05-24: FR-14 push-to-talk release observability was strengthened after release could still appear to do nothing if the provider returned no final transcript or an operator failed outside verbose mode. UI sessions now emit privacy-safe release diagnostics for provider finalization, protocol submission, and processing completion; release timeout warnings and operator failure warnings are surfaced in the transcript timeline; and visible UI operator diagnostics cover refine, translate, clipboard, and focused-input attempts without logging transcript text.
- 2026-05-24: FR-8/FR-14 Soniox finalization parsing was corrected after live UI evidence showed post-release partial text followed by a finalization timeout. The Swift Soniox adapter now processes `tokens` before handling same-frame `endpoint`/`finalized`/`finished` markers, so combined finalization frames promote text to final transcript instead of discarding token payloads and leaving the push-to-talk release without submitted text.
- 2026-05-24: FR-14 push-to-talk release fallback submission was added after live evidence showed Soniox can continue returning only partial hypotheses after release. The runtime now keeps the latest visible partial transcript in memory for the active session and, if provider finalization times out without final text, submits that latest partial through the normal protocol/refine/clipboard/input pipeline with an explicit warning. If no partial exists, the existing no-text warning remains. Late provider partial callbacks are suppressed after release submission commits so stale partial lines do not appear around processed output.
- 2026-05-24: FR-14 UI runtime diagnostics were de-duplicated after live verification showed the same push-to-talk fallback warning twice in the transcript timeline. UI runtime diagnostics now write to the diagnostics output once and rely on the runtime event sink for timeline/event-log delivery, while protocol-controller diagnostics still route through the UI event sink so operator warnings remain visible.
- 2026-05-24: FR-14 native UI monitoring layout was adjusted so the transcript timeline and event log live in separate `Transcript` and `Events` tabs. This preserves the existing transcript timeline controls and event log behavior while giving the selected monitoring view the full main-pane vertical space.

The hotkey monitor now ignores autorepeated key-down events for the configured push-to-talk key in both Quartz and AppKit paths, preserves normal `keyUp`/`flagsChanged` release handling, and keeps the explicit press-to-toggle fallback for environments where the event tap cannot start.
